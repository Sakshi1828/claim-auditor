# Dataset intelligence layer: findings

Generated by `python tools/profile_release.py` (module `auditor/catalog.py`). The verification engine is unchanged.
Profiles hold aggregates only: no sample or patient identifiers (checked by validation).

## Outputs
| File | What it is |
|---|---|
| `<release>.profile.json` | Every file and every clinical column: kind, pandas dtype, role, missing % (all rows and primary tumors), unique values, category counts or numeric summary, patient- vs sample-level granularity; matrix layers; survival endpoints; layer overlaps |
| `<release>.capabilities.json` | Only the analyses the data supports (n >= 30 informative primary tumors), with population, alternative denominator and limitations; usable groupings; 171 pre-registered association tests; claims that can never be verified |
| `validation.json` | 17 independent re-checks per release (re-read from the raw files with separate code) |
| `diff_A_vs_practice.json`, `diff_A_vs_random-test.json` | What changes between releases |
| `gap_probe.json` | 107 TRUE claims, one per capability, run through the current engine |

## The data (release A)
| File | Granularity | Size | Role | Supports |
|---|---|---|---|---|
| `clinical.tsv` | 1 row per sample (1,101 primary, 139 normal, 7 metastatic; 1,101 patients) | 193 columns | mixed | shares, counts, medians, subgroups |
| `survival.tsv` | 1 row per sample, patient-level values (1,097 patients) | OS/DSS/DFI/PFI + times | outcome | event counts/percentages, median follow-up (descriptive only) |
| `mutation_gene_level.tsv.gz` | gene x sample, 0/1 | 40,543 genes x 791 primary | predictor | % mutated, rank, within subgroups, co-occurrence |
| `copy_number_gistic.tsv.gz` | gene x sample, -2..2 | 24,776 genes x 1,080 primary | predictor | % amplified / deeply deleted, within subgroups |
| `protein_rppa.tsv.gz` | protein x sample, relative levels | 131 proteins x 742 primary | predictor | group comparisons (not absolute amounts) |
| `rna_hiseq.tsv.gz` | gene x sample, log2 | x 1,097 primary | predictor | group comparisons; **absent from envelopes** |
| `sample_manifest.csv`, `slide_manifest.csv` | sample / slide | 1,247 / 3,111 rows | metadata | coverage, slide counts |

**Clinical columns by role:** 73 predictor, 33 annotation (2012 study / Pan-Cancer labels), 32 metadata, 19 outcome,
36 free text (not aggregable). 165 are patient-level, 28 vary between a patient's samples. **85 of 193 columns are
more than 50% missing among primary tumors**, so the denominator matters for most claims.

**Layer coverage (primary tumors):** clinical 1,101 · survival 1,097 · RNA 1,097 · copy number 1,080 · mutation 791 ·
protein 742. Overlaps never exceed either layer (validated).

## Capability registry (release A)
176 capabilities: 98 category shares, 52 subgroup filters, 19 numeric summaries, plus mutation frequency, copy-number
frequency, protein levels, RNA expression, survival (descriptive), layer coverage and slides. 72 variables are usable
as groupings (>= 2 groups of >= 20 tumors).

**Associations:** 171 tests between key variables (subtype, ER/PR/HER2, histology, stage, nodes, menopause, margins,
radiation, top-8 mutated genes, age). 151 meet test assumptions; 34 remain significant after Bonferroni correction
(e.g. stage ~ nodes, PAM50 ~ ER, TP53 mutation ~ PAM50, menopause ~ age). These are exploratory and descriptive; the
auditor should never call a significance claim "supported" from them without a pre-specified analysis.

**Never verifiable with this release:** treatment response or benefit, causal claims, tumor grade (absent),
individual-patient predictions, anything outside this cohort.

## Validation
17/17 checks pass on release A, the practice envelope and the random test release: row and primary counts, every
column profiled, missingness and category counts re-derived independently, every capability points at a real column
with n >= 30, matrix sample counts, mutation frequencies, OS events, overlaps, no identifiers stored, p-values in [0, 1],
chi-square implementation against a textbook value. Validation caught and we fixed three profiler bugs: category labels
rewritten as "2.0" instead of "2", a misclassified code column, and an over-strict identifier check.

## Releases
- **Practice envelope vs A:** identical except the RNA file is missing. Expect the same for real envelopes:
  capabilities that need RNA disappear (176 -> 175).
- **Random test release vs A:** the diff finds exactly the planted changes: PAM50 Basal +40 (LumA -20, LumB -16, Her2 -4),
  ER status 60 Positive -> Negative, and changed mutation frequencies.

## What the current engine can't verify (probe: 107 true claims)
| Outcome | Claims |
|---|---|
| Verified (supported) | **17** |
| Not verifiable (insufficient evidence / not a claim) | **69** |
| **False alarm: true claim marked contradicted** | **21** |

**Not verifiable (69):** 59 category shares outside the hand-written topics (pathologic T, sub-stages like IIA,
surgery type, diagnosis method, Pan-Cancer clusters, menopause wording, new tumor events, follow-up status...),
7 numeric summaries other than age (lymph nodes examined, days to last follow-up...), 2 protein comparisons, 1 RNA
comparison. Copy-number and RNA values are never analysed by the engine.

**False alarms (21): the most serious finding.** The keyword router sends a claim to a checker that measures something
else and declares a true claim wrong:
- "MYC is amplified in 21.2% of tumors" -> cohort checker compared 21.2% with copy-number *coverage* (98.1%).
- "13.2% of tumors had a progression event" -> compared with survival-data coverage (99.6%).
- "HER2 protein is higher in Luminal A than Basal-like" (true: 0.31 vs -0.01) -> protein checker compared Luminal A
  with *all other subtypes*.
- "96.9% had no distant metastasis (distant_metastasis_present_ind2 = NO)" -> clinical checker measured the M1 share
  (the keyword matched; the polarity and column did not).
Many probe sentences use column-style wording, so the 21 overstate how often this happens with natural prose, but each
is a real routing error: the checker's keyword matched and its measurement did not answer the claim.

## After the false-alarm fixes (same 107 true claims)
| Outcome | Before | After |
|---|---|---|
| Verified (supported) | 17 | **24** |
| Not verifiable | 69 | 83 |
| False alarm (true claim marked contradicted) | 21 | **0** |

Fixes: checkers now give up instead of measuring something else (cohort checker on "X% of tumors *with* <layer>
data" and on "X% of the RPPA clusters"; subtype checker on other classifications; clinical checker on negations,
later events and other source columns); survival handles progression (PFI), recurrence (DFI) and cancer deaths (DSS);
protein comparisons use the two groups the claim names; a new copy-number checker (amplified / deeply deleted /
gained / lost, optionally within a subgroup); sub-stages (IIA...); a sentence with a percentage or a patient count is
no longer mistaken for a disclaimer. Locked in by `tests/routing_report.md` (14 claims, answers from plain pandas).

## What this means for the upgrade
1. Route by meaning, not keywords: a structured claim (target field + value, population, denominator, metric) checked
   against this catalog before any calculation.
2. A checker must refuse a claim whose target it does not measure (e.g. coverage checker vs "amplified in 21%").
3. Add generic executors for category shares, numeric summaries, copy number, and group-vs-group comparisons.
4. Keep significance claims as "insufficient evidence" unless a pre-specified test is named; offer the registry's
   tests as context only.
