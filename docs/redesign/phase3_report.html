Redesign · Phase 3 of 8

A calmer, more welcoming look

We added a welcome area that explains the app in one sentence, tidied the top bar, gave every box the same calm style, and added friendly waiting and empty screens. We used drawings in only 3 places, so it never feels busy. Nothing about how the app works was changed.

What changed, part by part

Welcome area (new, at the top)

AddedA calm welcome panel that says in plain words what the app does: “Is this research report right? Check it against the real data.”, with a short explanation and the 3 steps (Load, Review, Decide).
AddedA gentle drawing of a DNA helix that floats very slowly. It stops moving for anyone whose computer is set to reduce motion.
AddedA very faint tissue pattern behind it (5% strength), so the text stays just as easy to read.
HiddenOnce your results appear, the welcome panel steps aside so the results come first.
UnchangedThe real buttons (Check every claim, practice report, upload, envelope) are the same buttons, still in Step 1.

Top bar (navigation)

RestyledEach step link (Load, Review, Decide) now has a small icon, and the current step has a clear underline.
AddedOn phones and narrow windows, a “Menu” button opens a drawer with the same 3 links. Escape or choosing a link closes it.
UnchangedThe same 3 links, going to the same places, unlocking at the same times.

All boxes and cards

RestyledEvery card now has the same rounded corners, the same soft shadow and the same inner spacing, so the app looks like one piece.

Waiting and empty screens

AddedBefore you check a report, a friendly note with a cell drawing says “Your results will appear here”.
AddedWhile the app is already busy checking or unsealing, grey placeholder bars show where results will appear. They only show while the app is genuinely working.
AddedIf no claim is selected in Step 2, the existing “Select a sentence on the left.” now sits under a small cell drawing.

Which files changed

web/index.htmlThe page's look only: the welcome panel, the menu button, the empty and waiting screens, and their styles. One small view-only helper opens and closes the phone menu. Nothing that checks claims, saves results or talks to the server was touched.
tools/ui_baseline.pyOur checking tool: it now also allows the new Menu button and still fails if any old button or text disappears.
Everything elseNot touched: the checking engine, the data, the exports, the server.

How we checked that nothing broke

  1. We recorded all 574 pieces of text the page shows before the change, and checked them all again after: none missing.
  2. We clicked through everything: practice report, check, plain words, filters, tabs, confirm, override, the step links, the decision and export. All worked; the export said “valid”.
  3. On a phone-sized screen: the Menu opens and closes, the 3 links are the same, and nothing spills off the side.
  4. The waiting bars appear only while the app is checking; the welcome and empty screens step aside once results arrive.
  5. Our automatic comparison against the original page: no value, button, download or text removed or edited.

Nothing was skipped

Every change was a safe rearrangement of what was already there, so nothing had to be skipped.
